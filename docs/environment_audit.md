# Environment audit

Audit time: 2026-08-14, America/Chicago. Host: `Quest login node`.

| Capability | Observed value |
|---|---|
| OS | Red Hat Enterprise Linux 8.10, kernel 4.18.0-553.136.1.el8_10.x86_64 |
| Login Python | CPython 3.6.8 |
| Modern system Python | CPython 3.12.13 at `/usr/bin/python3.12` |
| CUDA compiler | Not available on the login node |
| NVIDIA driver/GPU | `nvidia-smi` cannot communicate with a driver; zero visible GPUs |
| PyTorch | Not installed before project bootstrap |
| Distributed launchers | Slurm `srun`/`sbatch` available; `torchrun`, Accelerate, and DeepSpeed absent initially |
| Package/environment tools | `uv` and Conda unavailable; Python 3.12 initially has no pip |
| Experiment tracking | W&B unavailable initially and disabled by default |
| Slurm GPU resources | A100 and H100 GRES are advertised on `gengpu*` and selected private partitions |

No CUDA software was changed. GPU packages are optional. The reproducible local path is a Python
3.12 virtual environment built from the exact pins in `pyproject.toml`; cluster users can instead
use `environment.yml`. `uv.lock` is intentionally absent because `uv` was not available during the
audit. A lock should only be generated by a compatible `uv` resolver and reviewed into source.

## Compatibility decision

The selected contract is PyTorch 2.8.0, Transformers 4.56.2, Accelerate 1.10.1, TRL 0.22.2,
and TransformerLens 2.16.1. The core CPU slice uses PyTorch/Transformers but does not import TRL,
Accelerate, PyArrow, or TransformerLens unless their adapters are invoked. This keeps task and
verifier tests runnable on a login node while making unavailable production backends fail with
actionable installation messages rather than silently switching algorithms.

Production model revisions and the MIB upstream commit are pinned in configuration and
`third_party/README.md`. Compatibility reports must be produced on a GPU node before a production
run is considered ready.
